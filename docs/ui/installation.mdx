# Installation

```bash
pnpm add @onaeko/ui
# or
npm install @onaeko/ui
```

## Peer dependencies

Required for the library:

```bash
pnpm add react react-dom
```

Also install when you use these surfaces:

| Peer              | Needed for                                                       |
| ----------------- | ---------------------------------------------------------------- |
| `react-hook-form` | Form (`Form`, `FormField`, `FormControl`, …) — **optional peer** |
| `react-is`        | Chart / Recharts — **optional peer**                             |

```bash
pnpm add react-hook-form react-is
```

Optional for validated Form stories and app schemas: `@hookform/resolvers` and `zod` (or another resolver-supported schema library).

## Styles

Import the package stylesheet once in your app root:

```tsx
import '@onaeko/ui/styles.css';
```

## Usage

```tsx
import { Button, Card, Input } from '@onaeko/ui';

export function Example() {
    return (
        <Card>
            <Input placeholder="Email" />
            <Button>Continue</Button>
        </Card>
    );
}
```

## Next.js

Use `transpilePackages: ['@onaeko/ui']` in `next.config` when needed.

### Client vs server

Interactive components that use browser APIs or client-only libraries ship with `"use client"` (Dialog, Form, Toast/Sonner, Calendar, Sidebar, etc.). Presentational pieces without client hooks can render on the server.

**SSR guidance:**

- Import `@onaeko/ui/styles.css` from a root layout (server-safe)
- Call `initTheme` / `setTheme` only on the client (e.g. `useEffect` in a client component)
- Mount `Toaster` in a client boundary (layout client shell or page marked `'use client'`)
- Prefer App Router client components for Form and other RHF-bound UIs

## Vite

Install the package, import styles, and use components like any other React library. Theme init can run at module scope in the client entry.
